🧭 Follow one booking through the whole ecosystem

  1. A customer pays for a flight. The payment is a tiny, fast, ACID write into a RDBMS (OLTP) such as Postgres or MySQL.
  2. At night, Sqoop bulk-copies those structured tables to HDFS; meanwhile website clicks arrive as events in Kafka, server logs are pushed by Flume, and NiFi moves other files with drag-and-drop flows.
  3. Everything lands raw in a Data Lake (HDFS, S3, ADLS, GCS) or its modern replacement Ozone, saved in files like Avro / Parquet. This is the ELT style: load first, transform later.
  4. YARN hands out CPU and memory while Spark (or old MapReduce/Pig) cleans the data; Hive and Impala let analysts query the files with SQL.
  5. The cleaned data is organised as Bronze → Silver → Gold tables in a Lakehouse (Iceberg / Delta) or a Data Warehouse such as Snowflake; dbt builds and tests the final SQL models.
  6. Airflow schedules and monitors all these steps as a DAG, while Docker and Terraform make the environments and infrastructure reproducible.
  7. Finally, managers open dashboards in Power BI / Tableau, analysts explore with Hue, users search logs with Solr, and data scientists train ML models — all written mostly in Python, Pandas and SQL on platforms like Databricks.

⚖️ The two ideas behind everything

OLTP vs OLAP

OLTP = quickly changing transactional data (databases). OLAP = historical analysis (warehouses, lakes, lakehouses). Open topic

ETL vs ELT

ETL transforms before loading (data warehouse). ELT loads raw data first and transforms afterwards (lakes, lakehouses). Open topic
