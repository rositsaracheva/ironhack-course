Module 1: Programming Foundations & Analytics (Python, Pandas, NumPy, SQL)

Syllabus Items 1 – 3
#1 Python in Data Engineering
Click to view deep dive

Python is the universal language of modern Data Engineering due to its portability, dynamic typing, and massive package ecosystem.

  • Paradigms: Supports Functional (lambda, map, filter), Scripting (automation, cron jobs), and Object-Oriented Programming (OOP).
  • Development Environments: Jupyter Notebooks (EDA), VS Code / PyCharm (production scripts, modules, CI/CD).
  • File Formats: .py for version-controlled production code, .ipynb for interactive data exploration.
  • Cross-Product Compatibility: Native first-class runtime across Databricks, Snowflake (Snowpark), Apache Spark (PySpark), Splunk, and Apache Flink.
  • Key Constructs:
    • __init__: Constructor method initializing state in OOP classes; also __init__.py designates directory as a Python package.
    • Built-in Functions: Standard library utilities (print(), len(), type(), enumerate(), zip()).
    • User-Defined Functions (UDFs): Custom logic packaged for reusable row-by-row or vectorized operations in Spark and SQL.
🎯 Interview Question: "Why is Python preferred over Java/Scala for many modern data pipelines?"
Answer: "Python accelerates development velocity, integrates seamlessly with data science/ML frameworks, and via PySpark and Snowpark, the compute is executed on underlying JVMs or C++ engines without Python speed bottlenecks."
#2 Data Manipulation: Pandas, NumPy & Python Structures
Click to view deep dive

Core structures utilized for in-memory data processing, cleaning, and mathematical operations.

Data Structure Mutability Syntax Duplicates? Primary Use Case
List Mutable [1, "apple", True] Allowed (Ordered) Dynamic collections, queues, iterating over datasets.
Tuple Immutable (10, 20) Allowed (Ordered) Fixed record schemas, dictionary keys, function multiple returns.
Set Mutable {"a", "b", "c"} Disallowed (Unique, Unordered) Deduplication, membership testing (O(1) lookups), mathematical unions/diffs.

  • NumPy (Numerical Python): Provides N-dimensional arrays (ndarray) with contiguous memory allocation and vectorized C-level operations. Ideal for linear algebra and fast array math.
  • Pandas: Built on NumPy; provides 2D labeled DataFrame structures (rows & columns) with powerful indexing, filling nulls, grouping, and merging messy data.
⚠️ Senior Interview Distinction: Pandas is single-node and runs entirely in memory (RAM). If data exceeds memory, it crashes with Out-Of-Memory (OOM). For distributed datasets, transition to PySpark or Polars.
#3 SQL (Structured Query Language) & Query Optimization
Click to view deep dive

The universal declarative query language for relational databases, data warehouses, and distributed engines.

  • SQL Sublanguages:
    • DDL (Data Definition Language): CREATE, ALTER, DROP, TRUNCATE.
    • DML (Data Manipulation Language): INSERT, UPDATE, DELETE, MERGE.
    • DQL (Data Query Language): SELECT and data retrieval expressions.
  • Core Clauses Execution Order: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT.
  • Joins:
    • INNER JOIN: Returns matching records from both tables.
    • LEFT/RIGHT OUTER JOIN: Preserves all rows from one side plus matched rows.
    • FULL OUTER JOIN: Combines both sides, filling unmatched fields with NULL.
    • CROSS JOIN: Cartesian product (every row combined with every other row).
  • CTEs & Window Functions: 
    WITH RankedSales AS (
  SELECT employee_id, region, sales_amount,
         RANK() OVER (PARTITION BY region ORDER BY sales_amount DESC) as rank
  FROM sales
)
SELECT * FROM RankedSales WHERE rank <= 3;
  • Performance Optimization & Tuning:
    • EXPLAIN ANALYZE: Reads the physical execution plan (Table Scan vs. Index Seek, join algorithms, estimated vs. actual rows).
    • Indexing: B-Tree (standard), Hash, Bitmap indexes for fast point-lookups.
    • Partitioning: Dividing large tables physically by date/region to achieve Partition Pruning.
🎯 Interview Question: "What is the difference between WHERE and HAVING?"
Answer: "WHERE filters rows *before* aggregation takes place; HAVING filters grouped records *after* the GROUP BY aggregation is computed."

Module 2: Storage Paradigms (RDBMS, Data Warehouse, Data Lake, Lakehouse)

Syllabus Items 4 – 7
#4 Relational Databases (DBMS) & OLTP
Click to view deep dive

Online Transaction Processing (OLTP) systems power operational day-to-day applications requiring high-concurrency, low-latency writes and updates.

  • ACID Guarantees:
    • Atomicity: "All or nothing" — if any part of transaction fails, the entire transaction rolls back.
    • Consistency: Ensures transactions transition database from one valid state to another, enforcing foreign keys and constraints.
    • Isolation: Concurrent transactions execute without cross-contamination (Isolation levels: Read Committed, Repeatable Read, Serializable).
    • Durability: Once committed, data persists on non-volatile disk even during power outage (Write-Ahead Logging / WAL).
  • Characteristics: Highly normalized (3NF), row-based storage, Schema-on-Write, write-heavy workloads (orders, banking, e-commerce cart).
  • Leading Vendors: PostgreSQL, MySQL, Oracle, Microsoft SQL Server, SQLite.
🎯 Interview Question: "Why not run analytics dashboards directly on the production OLTP database?"
Answer: "Analytical queries scan millions of rows and aggregate data, which consumes CPU/RAM and locks tables, degrading the performance and availability of live operational customer transactions."
#5 Data Warehouses & OLAP
Click to view deep dive

Online Analytical Processing (OLAP) repositories consolidated across an enterprise to support BI, executive reporting, and historical trend analysis.

  • Characteristics: Denormalized schemas (Star schema, Snowflake schema, Fact & Dimension tables), read-heavy, batch-loaded via ETL/ELT pipelines.
  • Schema-on-Write: Strict schema validation before data is written into tables.
  • Modern Cloud DWs: Snowflake, Google BigQuery, Amazon Redshift, Azure Synapse. Modern cloud DWs now support semi-structured types (JSON, VARIANT) and decouple compute from storage.
🎯 Interview Question: "What is the difference between Star Schema and Snowflake Schema?"
Answer: "In a Star Schema, a centralized Fact table connects directly to denormalized Dimension tables (faster query joins). In a Snowflake Schema, Dimension tables are normalized into sub-tables (reduces data redundancy, but requires more joins)."
#6 Data Lakes & Schema-on-Read
Click to view deep dive

Massive, low-cost repositories storing structured, semi-structured, and unstructured data (text, video, audio, logs) in its raw, native format.

  • Storage Technologies: AWS S3, Azure Data Lake Storage (ADLS Gen2), Google Cloud Storage (GCS), HDFS.
  • Consistency Model: Often follows BASE (Basically Available, Soft state, Eventually consistent) rather than strict ACID.
  • Schema-on-Read: Raw files are ingested as-is without validation; schema is applied dynamically only when a compute engine (Spark, Hive) reads the data.
  • Risk — "Data Swamp": Ingesting files without data catalogs, metadata governance, or lifecycle policies turns a Data Lake into an unsearchable, messy swamp.
#7 Data Lakehouses (The Modern Convergence)
Click to view deep dive

Architecture Formula: Data Lakehouse = Low-Cost Cloud Object Storage + Open Table Format (ACID & Metadata Layer)

  • Bridges the gap between the cost-effectiveness and flexibility of Data Lakes with the ACID transactions, data governance, and fast BI querying of Data Warehouses.
  • Open Table Formats: Delta Lake (Databricks), Apache Iceberg, Apache Hudi.
  • Medallion Architecture:
    • 🥉 Bronze: Raw, unmodified ingested data (append-only history).
    • 🥈 Silver: Cleaned, validated, enriched, deduplicated data (source of truth).
    • 🥇 Gold: Business-level aggregated reporting metrics and dimensional tables ready for BI and ML.
🎯 Interview Question: "Why are companies migrating from traditional Data Warehouses to Lakehouses?"
Answer: "Lakehouses eliminate duplicate storage and ETL pipelines between separate data lakes and warehouses. They avoid vendor lock-in with open file formats (Parquet) and support both SQL analytics and Machine Learning on a single copy of data."

Module 3: Distributed Systems & Big Data (HDFS, YARN, MapReduce, Hive, Impala)

Syllabus Items 1 – 11 (Pages 3–5)
Hadoop Core Distributed File System (HDFS) & Master-Slave Architecture
Click to view deep dive

HDFS is a distributed, fault-tolerant file system designed to run on commodity hardware clusters.

  • Block Storage: Files are split into contiguous large chunks. Default Block Size = 128 MB (avoids master memory bottlenecks).
  • Replication: Default replication factor is 3x (1 local node, 1 on same rack, 1 on remote rack) ensuring hardware resilience.
  • Daemons:
    • NameNode (Master): Manages metadata, file namespace tree, and maps data blocks to DataNodes. High Availability (HA) mode uses Active/Standby with ZooKeeper.
    • DataNode (Slave): Stores physical blocks on disk and performs read/write requests from clients.
🎯 Interview Question: "Why does HDFS suffer from the 'Small Files Problem'?"
Answer: "Each file, directory, and block consumes ~150 bytes of memory in the NameNode. Storing millions of small KB-sized files exhausts the NameNode's RAM while underutilizing cluster disk storage."
Resource Manager YARN (Yet Another Resource Negotiator)
Click to view deep dive

The centralized cluster operating system decoupled from MapReduce in Hadoop 2.0 to allocate compute resources dynamically.

  • Components:
    • ResourceManager (Master): Global cluster arbiter of compute (CPU cores, RAM).
    • NodeManager (Slave): Runs on each worker machine, tracking container health and resource usage.
    • ApplicationMaster: One instance spawned per submitted job to negotiate resources with the ResourceManager and coordinate tasks.
    • Containers: Logical abstractions encapsulating memory and CPU allocations where tasks run.
  • Schedulers: FIFO, Capacity Scheduler, Fair Scheduler (Round Robin, LRU).
Processing & Ingestion MapReduce Execution Model & Apache Sqoop
Click to view deep dive
  • MapReduce Phases:
    1. Map: Processes input splits in parallel, applying transformations to output (key, value) pairs.
    2. Shuffle & Sort: System sorts and partitions intermediate data across the network so identical keys land on the same reducer (I/O intensive bottleneck).
    3. Reduce: Aggregates values per key and writes final output sequentially to HDFS.
  • Apache Sqoop (SQL-to-Hadoop): Bulk transfer tool connecting relational databases (MySQL, Oracle) to HDFS/Hive using JDBC. Spawns map-only jobs (default 4 mappers) for high-throughput parallel import/export. (Now retired in the Apache Attic).

Module 4: Real-Time Streaming & Orchestration (Spark, Kafka, NiFi, Airflow)

Syllabus Items 12 – 17
In-Memory Compute Apache Spark & PySpark Internal Architecture
Click to view deep dive

General-purpose distributed in-memory compute engine executing workloads up to 100x faster than MapReduce.

  • Core Abstractions:
    • RDD (Resilient Distributed Dataset): Immutable, partitioned collection of records evaluated in memory.
    • DataFrame (DF): Distributed table with named columns, optimized by the Catalyst Query Optimizer and Tungsten Execution Engine.
  • Transformations vs. Actions:
    • Transformations (LAZY): select(), filter(), groupBy(), join(). Build a Logical Directed Acyclic Graph (DAG) without triggering computation.
    • Actions (EAGER): show(), count(), collect(), write. Trigger execution across worker nodes.
  • Entry Points Evolution: SparkContext (sc) → SparkSession (spark) unified in Spark 2.0+.
🎯 Interview Question: "What is Narrow vs. Wide Transformation in Spark?"
Answer: "In a Narrow Transformation (e.g. map, filter), each child partition depends on only one parent partition—no data moves across the network. In a Wide Transformation (e.g. groupBy, join), data must be shuffled across network partitions, which is expensive."
Orchestration Apache Airflow (Workflow Orchestration)
Click to view deep dive

Created by Airbnb; Python-native workflow orchestration platform managing complex pipeline dependencies.

  • DAG (Directed Acyclic Graph): Collection of tasks with directional relationships and no circular dependencies.
  • Operators & Tasks: BashOperator, PythonOperator, SparkSubmitOperator, SnowflakeOperator. Task dependencies defined via bitshift: task1 >> [task2, task3] >> task4.
  • Architecture: Webserver (UI), Scheduler (triggers jobs), Metastore (PostgreSQL state), Executor (Sequential, Local, Celery, Kubernetes).
Event Streaming Apache Kafka & Event-Driven Architecture
Click to view deep dive

High-throughput, distributed append-only publish-subscribe event streaming log developed at LinkedIn.

  • Core Concepts:
    • Producer: Publishes events to Kafka Topics.
    • Broker: Server nodes storing partitioned immutable logs (default port 9092).
    • Consumer: Reads events via a Pull model, tracking progress via consumer offsets.
    • Partitions & Replication: Topics are split into partitions for parallel throughput and replicated across brokers for durability.
  • Apache Flume Comparison: Flume uses a Push model configured with Source-Channel-Sink agents designed primarily to funnel webserver logs directly into HDFS. Kafka is general-purpose and decouples arbitrary producers and consumers.
Dataflow Automation Apache NiFi (Flow-Based Visual ETL)
Click to view deep dive

Created by the NSA; provides a browser-based drag-and-drop UI (port 8443) for automated data ingestion, protocol routing, and transformation.

  • FlowFile: Fundamental unit consisting of payload content + key-value metadata attributes.
  • Processors: Over 300 pre-built connectors for reading, routing, converting, and delivering files (Batch & Streaming).
  • Data Provenance: Automatically records complete end-to-end audit lineage of every record's modification history.

Module 5: Modern Data Stack (dbt, Iceberg, Ozone, Databricks, Snowflake, IaC)

Syllabus Items 21 – 30
Open Table Format Apache Iceberg & Modern Open Lakehouses
Click to view deep dive

High-performance open table format designed by Netflix for huge multi-petabyte analytical tables.

  • Hidden Partitioning: Automatically abstracts date/time conversions, preventing user query errors.
  • ACID Transactions & Snapshot Isolation: Readers see consistent snapshots while writes occur concurrently.
  • Schema Evolution: Safely add, rename, reorder, or drop columns without breaking legacy Parquet data files.
  • Engine Independence: Query the exact same Iceberg table concurrently from Snowflake, Databricks, Spark, Trino, and Flink.
Next-Gen Storage Apache Ozone (Scalable HDFS Alternative)
Click to view deep dive

Distributed, open-source Object Store designed to scale beyond HDFS limits (up to billions of objects).

  • Decouples namespace management (Ozone Manager) from block storage (Storage Container Manager).
  • Solves the Small Files Problem: Packs small files into storage containers, avoiding master memory exhaustion.
  • Native S3-compatible API and transparent integration with Hadoop ecosystem workloads.
ELT Transformation dbt (Data Build Tool)
Click to view deep dive

The industry-standard transformation framework enabling SQL developers to follow software engineering best practices.

  • The "T" in ELT: dbt does not extract or load data; it runs SQL transformations inside your existing warehouse (Snowflake, BigQuery, Databricks).
  • Models & Jinja: SQL files written with {{ ref('upstream_model') }} to build lineage graphs automatically.
  • Testing & Documentation: Built-in YAML tests (unique, not_null, relationships) and auto-generated documentation portals.
  • Version Control: Pure code stored in Git repositories, integrated with CI/CD deployment workflows.
DevOps & Cloud Containerization (Docker) & Infrastructure as Code (Terraform)
Click to view deep dive
  • Docker: Packages application code, libraries, and system dependencies into portable Containers running identically across dev, test, and cloud production environments.
    • Image vs. Container: An image is the immutable blueprint (Docker file); a container is a live running instance.
    • Docker Compose: Multi-container orchestration tool defined in YAML files.
  • Terraform: Declarative Infrastructure-as-Code (IaC) tool by HashiCorp. Defines cloud infrastructure (AWS S3, Snowflake warehouses, Databricks clusters) in .tf files, tracking state in terraform.tfstate.
