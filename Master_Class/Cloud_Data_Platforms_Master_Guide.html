📊 File Formats: CSV vs. JSON vs. Avro vs. Parquet vs. Delta Click to open

Row-based (CSV, Avro) writes entire rows together (fast for writing/streaming). Columnar (Parquet, ORC, Delta) groups each column together (3–5x smaller & up to 10x faster for analytical queries because it only reads the columns you ask for!).

FormatTypeWhen to Use in Real Life
CSVRow (Text)Small manual files; slow & has no data type metadata.
JSONSemi-structuredWeb APIs & clickstreams; query in Snowflake using VARIANT + LATERAL FLATTEN.
AvroRow (Binary)Kafka streaming & write-heavy pipelines; best schema evolution.
ParquetColumnar (Binary)Big Data analytics; compressed with Snappy/ZSTD; read-only.
Delta LakeParquet + LogDatabricks default; adds ACID, UPDATE/DELETE, and Time Travel to Parquet.
❄️ Snowflake Table Types: Permanent vs. Transient vs. Temporary Click to open
  • Permanent Table (Default): Lives until dropped. Has Time Travel (1–90 days) + 7-day Fail-safe. Best for final production business data.
  • Transient Table (CREATE TRANSIENT TABLE): Lives until dropped, but has NO Fail-safe (and 0–1 day Time Travel). Saves 30–50% on storage overhead! Best for staging / intermediate ETL tables.
  • Temporary Table (CREATE TEMPORARY TABLE): Lives only inside your current worksheet session. Automatically deleted when your session closes. Best for scratch calculations.
Real-World Interview Question: "How do you reduce storage costs on staging tables that get reloaded every night?" → "Make them Transient tables so you don't pay for 7 days of Fail-safe storage on temporary ETL data."
👁️ Views: Standard View vs. Materialized View vs. Secure View Click to open
  • Standard View: Just a saved SQL query. Uses 0 storage; re-runs every time you query it. Good for hiding columns or simplifying joins.
  • Materialized View: Pre-computes and physically saves the result table, automatically updating in the background when the base table changes. Costs storage, but makes heavy BI dashboards 10x faster!
  • Secure View: Hides the underlying SQL code and prevents query-optimizer tricks from leaking hidden rows. Required when sharing data externally.
📦 Stages (Snowflake) vs. Volumes (Databricks) Click to open

Before raw files (.csv, .parquet, .avro) become SQL tables, they need a governed "landing folder":

  • In Databricks — Unity Catalog Volume: Accessed like a folder path: /Volumes/catalog/schema/volume_name/file.csv.
  • In Snowflake — Stage:
    • User Stage (@~): Private to your user.
    • Table Stage (@%table): Tied to one table.
    • Named Internal Stage (@my_stage): Shared folder inside Snowflake.
    • External Stage: Points to AWS S3 / Azure / GCP via a secure STORAGE INTEGRATION (no hardcoded keys!).
Best Practice: Stage compressed files (ZSTD/GZIP Parquet or CSV) sized 100–250 MB so all nodes in your Virtual Warehouse load them in parallel!
🚚 Data Ingestion: COPY INTO (Batch) vs. Snowpipe (Continuous) Click to open
  • COPY INTO (Bulk Batch): Uses your own Virtual Warehouse. Best for scheduled loads (hourly/nightly), large historical backfills, or transforming columns on the fly during load.
  • Snowpipe (Continuous Serverless): Created with CREATE PIPE ... AUTO_INGEST = TRUE. Uses S3 event notifications (SQS) to load small files automatically within minutes of arrival using serverless compute.

(In Databricks, the equivalent of Snowpipe is Auto Loader cloudFiles).

⏪ Time Travel, Fail-safe, Undrop & Zero-Copy Cloning Click to open
  • Time Travel (Self-Service SQL): Query or restore past versions!
    • Snowflake: SELECT * FROM tbl AT(OFFSET => -300); or UNDROP TABLE tbl;
    • Databricks: SELECT * FROM tbl VERSION AS OF 2; or RESTORE TABLE tbl TO VERSION AS OF 2;
  • Fail-safe (Snowflake Only): 7-day emergency window after Time Travel expires. Users cannot query it — only Snowflake Support can recover it.
  • Zero-Copy Cloning: CREATE TABLE bookings_dev CLONE bookings; Creates an instant copy with $0 extra storage by copying only metadata pointers to the existing micro-partitions!
🔄 Continuous Pipelines: Streams & Tasks (Snowflake) vs. Medallion (Databricks) Click to open
  • Snowflake Streams & Tasks:
    • Stream: Tracks only new/changed rows on a table (Change Data Capture / CDC).
    • Task: Runs a scheduled SQL query or Stored Procedure (e.g., every 15 mins) to move new rows from the Stream into your final table.
  • Databricks Medallion Architecture:
    • 🥉 Bronze: Raw ingested data.
    • 🥈 Silver: Cleaned, deduplicated, joined data.
    • 🥇 Gold: Business KPIs & aggregated tables ready for BI.
