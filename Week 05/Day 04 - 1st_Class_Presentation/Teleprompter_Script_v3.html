🛡️ Defense Bank: 12 Questions the Teacher / Class Might Ask You
Q1: Why don't we use Parquet for EVERYTHING (including Kafka streaming)?
"Because Parquet is expensive to write. To organize data by columns and calculate min/max stats, Parquet must buffer a large batch of rows in memory. For real-time streaming or writing row-by-row, Avro is much faster."
🇪🇸 Porque Parquet es costoso al escribir (necesita acumular muchas filas en memoria para separarlas por columnas). Para escribir fila a fila en tiempo real, Avro es mucho más rápido.
Q2: Where is the schema stored in Avro vs. Parquet?
"In Avro, the schema is stored in JSON format at the top (header) of the file. In Parquet, the schema and column statistics are stored at the very bottom (footer) because Parquet writes the data first and writes the metadata summary at the end."
🇪🇸 En Avro va arriba en la cabecera (JSON header). En Parquet va abajo del todo en el pie (footer) junto con las estadísticas min/max.
Q3: What is 'Schema Evolution' and which format is best at it?
"Schema Evolution is the ability to add, rename, or remove columns without breaking old files or pipelines. Avro is the best at it because its JSON header resolves old and new schemas using default values."
🇪🇸 Es añadir o cambiar columnas sin romper los archivos viejos. Avro es el mejor gracias a su cabecera JSON con valores por defecto.
Q4: Why does Parquet compress 85% better than CSV or Avro?
"Because Parquet puts values of the exact same data type side-by-side. For example, if 'London' repeats 10,000 times in the City column, Dictionary Encoding and Run-Length Encoding store 'London' just once with a counter!"
🇪🇸 Porque junta datos del mismo tipo seguidos en disco. Si 'London' se repite 10.000 veces en una columna, lo guarda una sola vez con un contador.
Q5: Can I open an Avro or Parquet file in Excel or Notepad?
"No, because both Avro and Parquet are binary formats made for machines. You need Spark, Hive, Impala, or Python (pandas / pyarrow) to read them."
🇪🇸 No, porque ambos son binarios. Necesitas Spark, Hive, Impala o Python para leerlos.
Q6: Are Avro and Parquet files splittable in HDFS?
"Yes! Both are fully splittable. Avro uses sync markers between row blocks, and Parquet divides files into independent Row Groups, so multiple Spark executors can process the same file in parallel."
🇪🇸 ¡Sí! Ambos se pueden dividir en HDFS para procesarse en paralelo con varios ejecutores de Spark.
Q7: What compression codec is most commonly used with Parquet?
"Snappy is the default in Spark, Hive, and Impala because it offers the best balance between fast CPU decompression speed and small file size."
🇪🇸 Snappy es el estándar por defecto porque equilibra muy bien velocidad y compresión.
Q8: What is the difference between Parquet and ORC?
"Both are binary columnar formats with very similar features. Parquet is the standard for Spark, Impala, Cloudera, and Databricks, while ORC was originally optimized for Hive."
🇪🇸 Ambos son columnares binarios; Parquet es el estándar en Spark/Impala/Databricks y ORC nació para Hive.
